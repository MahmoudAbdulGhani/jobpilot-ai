# Free worldwide discovery and reviewed applications

The discovery page offers three separately selected public sources. JobTech covers primarily Swedish ads, Jobicy provides a recent remote catalog, and Job Opportunities API provides worldwide employer-direct listings. The worldwide adapter uses only `GET /public/jobs` and `GET /public/jobs/{id}`. It needs no API key or paid subscription. Its public search is limited to a single page of at most 50 listings for each filter set; it cannot page through every matching job. The worldwide search sends `has_description=true&include_description=true`, shows a short text excerpt in results, and excludes rows without source advert text. A reviewed import now requires source advert text for every source. When an older imported job lacks a description, opening it automatically tries its fixed public source once through a bounded provider. If the source still has none, the UI says so and the user must choose another described listing. Saved titles, notes, and existing descriptions are not overwritten. JobPilot does not impose a per-user job-search quota.

`GET /api/discovery/sources` publishes the supported controls and source limitations. `GET /api/discovery` accepts `country`, `region`, `city`, `eligibility`, `remote`, `q`, `sort`, `offset`, and `source`. The old Jobicy `location` input remains accepted as an eligibility alias. Unsupported combinations return 422. For worldwide search, country is an ISO two-letter code, region is a two-letter US state code and requires country `US`, and city is free text. JobTech resolves exact country, region, and municipality names through the official taxonomy API before sending concept IDs to JobSearch. JobTech accepts one geography filter at a time because its upstream multi-place search promotes local results rather than strictly intersecting places. Jobicy's eligibility filter matches source-stated text within its cached catalog; it does not imply legal work authorization. Worldwide and JobTech listings have unknown applicant eligibility unless the employer's description states it.

Worldwide search uses a shared five-minute cache for each filter set, a ten-minute detail cache, and a durable shared rate claim capped at 35 provider requests per minute. Transport follows no redirects, accepts only fixed API paths, limits decoded responses to four megabytes, and never logs provider bodies. Application links must be HTTPS and are never fetched by JobPilot. Search and preview preserve the source ID, upstream source name, structured workplace geography, remote inference, and employer link in the reviewed import snapshot. Existing saved jobs need no migration; the existing `discovery_cache` table stores the new cache entries.

Imported jobs lead to the existing application pack. A confirmed CV, saved profile, job description, and AI consent are still required for generation. The pack's evidence checks reject unsupported AI claims. Job-fit analysis shows job requirements not evidenced in saved facts. The user reviews and approves a pack, then chooses the existing confirmed email flow or the employer's site. No automated employer form submission is added. If AI is disabled, the original listing and manual application path remain available.

Provider transport tests use `httpx.MockTransport` and block real transport. The frontend tests mock all API calls. Database-backed integration and guarded browser tests require the repository's isolated PostgreSQL test database; they must not be pointed at a personal or production database. The configured remote `jobpilot_test` database was unavailable during this implementation, so those checks remain outstanding.
